# 流程使用教程 —— 面向终端用户（填单人 / 审批人）

> 读者：在 Kimpo 里**填单据、提交审批、办理审批**的业务用户。不需要任何配置知识，更不需要编程知识。
> 读完你会：提交一张走审批的单据、在任务中心处理别人送来的审批、看懂单据的每种状态、知道填错了/被退回了该怎么办。
> 如果你要**设计**审批流（画流程图、配审批人），请看 [tutorial-for-app-developers.md](tutorial-for-app-developers.md)；设置项的完整解释在 [for-end-users.md](for-end-users.md)。

---

## 1. 你会在三个地方遇到"流程"

1. **表单上的「提交」按钮**：如果一张表单绑定了审批流程，填报页面的动作栏里、「保存」按钮旁边会出现**「提交」**按钮。点它，单据就进入审批。
2. **左侧菜单的「任务中心」**：所有等你审批的、你审批过的、抄送给你的、你自己发起的单据，都聚合在这里（跨所有应用）。
3. **通知**：有单据送到你面前、或有人催办时，你会收到站内通知，点通知可以直达办理页面。

一句话理解流程：**提交 = 把单据放上审批传送带**。单据被锁住，按预先画好的路线一站一站送到该审批的人面前，全部通过后单据"盖章定局"。

---

## 2. 提交一张单据

**第 1 步：填单。** 像平常一样新增单据、填写内容。这时单据还是普通草稿，随便改。

**第 2 步：点「提交」。** 系统会**先自动保存，再提交**——你不用担心没保存就提交丢内容。

提交时可能遇到三种情况：

| 情况 | 你会看到 | 说明 |
|---|---|---|
| 表单绑定了一条明确的流程 | 直接提交成功，单据变为「审批中」并转为只读 | 最常见情况 |
| 表单绑定了多条流程，系统无法自动判断走哪条 | 弹出**「选择审批流程」**窗口，列出候选流程 | 选一条后提交；点取消则什么都不发生，单据还是草稿 |
| 表单没有绑定流程 | 提示"未绑定流程"，单据只做普通保存 | 这不是报错；该表单本来就不走审批 |

**提交之后：**

- 单据整体**锁定只读**（除非某个审批环节明确放行了几个字段给当时的办理人改）；
- 你可以在「任务中心 → 我发起」里随时查看它走到了哪一步；
- 审批人会收到待办任务和通知。

### 单据的四种状态

| 状态 | 含义 | 还能改吗 |
|---|---|---|
| （未提交） | 普通草稿 | 随便改 |
| **审批中** | 正在传送带上 | 只读（不能改、不能删） |
| **已通过** | 审批全部走完、同意 | 锁定，按表单常规权限处理 |
| **已拒绝** | 被终止/拒绝 | 回到可编辑，改完可以再提交 |

## 3. 任务中心：你的审批工作台

左侧菜单打开**任务中心**，有四个页签：

- **待办**：等你处理的任务，菜单上有数量角标。这是你最常用的页签。
- **已办**：你处理过的历史任务。
- **抄送**：知会你的单据——不需要你审批，看一眼点**「已阅」**即可（可勾选多条批量已阅）。
- **我发起**：你提交的所有单据，看它们各自走到哪一步了。

点任意一行，进入**办理面板**：

```
┌────────────────────────────┬──────────────┐
│                            │  流程进度图    │
│   单据内容（只读）           │  （走到哪一站  │
│                            │   一目了然）   │
├────────────────────────────┴──────────────┤
│  审批意见框     [同意]  [不同意]  [暂存]     │
└───────────────────────────────────────────┘
```

右侧还有「讨论」页签，可以针对这张单据留言交流。

## 4. 办理一个审批任务

**第 1 步：打开任务。** 从待办列表或通知点进办理面板。

**第 2 步：认领（有时需要）。** 如果这一站配的是"多个人里谁先处理谁办"（或签），任务需要先**认领**——打开面板会自动帮你认领。认领后别人会看到"已被你认领"；如果你不想办了，可以**释放**让别人接手。

**第 3 步：看单据、填意见。** 左侧通读单据内容。意见框是否必填由流程设计决定——必填时不写意见提交不了。写了一半有事走开？点**「暂存」**，意见保留在你名下，下次接着写。

**第 4 步：表态。**

- **同意**：放行，单据去往下一站。
- **不同意**：后果由流程设计预先定好，通常是三种之一——**整单终止**（单据变"已拒绝"）、**退回上一步**（回到上一站重办）、**退回发起人**（打回给填单人改）。
- 有些环节的按钮叫**「完成/提交」**而不是"同意"——那是**办事环节**，比如要你补填几个字段再交下去，没有"不同意"的概念。要求补填的字段没填完是提交不了的。

**批量审批**：待办列表里勾选多条、一键同意。要求必填意见或必须补填字段的任务会被自动排除并告诉你原因。

**几个你可能遇到的自动行为**（都是正常的）：

- 你刚在上一站审过、这一站又是你 → 系统默认**自动通过**，不用审两次（进度图会标"自动通过"）；
- 审批人是发起人自己 → 默认自动通过；
- 某站没解析出任何审批人（比如审批人离职）→ 按预设兜底处理（通常转给管理员），单据不会卡死。

## 5. 单据被退回了怎么办（发起人视角）

被"退回发起人"的单据会回到你手里：

1. 你会收到通知，「我发起」里也能看到它的状态；
2. 打开单据修改——如果流程要求某些字段**清空重填**，打开时会有提示；
3. 改完重新**提交**。默认**直达**当初退回你的那一站，中间已经审过的人不用重复审（流程也可能配置为重走全程）。

---

## 6. 发起人的两个特权

- **撤回**：提交后发现填错了？只要下游**还没有任何人实际处理**（没人认领、没人办结），你可以撤回——单据回到普通草稿状态，改完重新提交。一旦有人动过就不能撤了，这时只能联系审批人帮你点"不同意-退回发起人"。
- **催办**：单据卡在某一站太久，可以点**催办**，当前办理人会收到提醒通知（短时间内不能对同一任务反复催，防骚扰）。

---

## 7. 其他你可能用到的协作能力

| 能力 | 场景 |
|---|---|
| **转办** | 这个任务不该我办 / 我办不了 → 转给另一个人，记录上会写明"由谁代谁办理" |
| **委托代理** | 休假前设置"某段时间内我的审批自动交给某人"，期间任务直接生成给代理人 |
| **加签** | 会签时临时拉人：先让某人审完再回到我（前加签）、我审完再给某人（后加签）、拉人和我一起审（并加签） |
| **超时提醒** | 任务停留太久系统自动提醒；有的环节还会配自动升级（如超时自动转交/自动通过） |

## 8. 常见问题

**Q：为什么我的表单上没有「提交」按钮？**
A：这张表单没有绑定审批流程，只有普通「保存」。需要走审批请联系应用管理员。

**Q：点了提交却弹出一个"选择审批流程"的窗口？**
A：这张表单挂了多条流程且系统无法自动判断该走哪条，选一条继续即可；不确定选哪条问管理员。点取消不会有任何影响。

**Q：审批中的单据我能改吗？**
A：默认全程只读。只有当前环节明确放行给当前办理人的个别字段可以改。

**Q：单据被拒绝了，数据丢了吗？**
A：没有。被拒绝的单据回到可编辑状态，内容都在，修改后可以重新提交。

**Q：我看不到某条待办了？**
A：可能是或签任务被同组其他人抢先认领办结了，或发起人撤回了单据。到「已办」或通知里可以查证。

**Q：审批记录能改吗？**
A：不能。每一步操作（谁、何时、什么动作、什么意见）都是不可篡改的流水，进度图 + 流水就是完整的审计链。
