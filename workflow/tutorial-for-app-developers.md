# 流程搭建教程 —— 面向应用开发者

> 读者：在 Kimpo 里**搭建应用**的人——你负责建模板、画审批流、把流程挂到表单上，让业务用户能提交审批。不需要写代码。
> 读完你会：从零画出一条流程、发布它、**把它绑定到模板**（本教程的重点）、理解提交时系统怎么决定走哪条流程、以及改版后老单据会怎样。
> 配套：办理视角的教程在 [tutorial-for-end-users.md](tutorial-for-end-users.md)；12 类节点与全部设置项的逐项解释在 [for-end-users.md](for-end-users.md)；引擎内部原理在 [for-human-developers.md](for-human-developers.md)。

---

## 1. 先把五个概念说人话

流程这套东西，概念其实只有五个，全部可以用"公交线路"来理解：

| 概念 | 说人话 | 类比 |
|---|---|---|
| **流程定义** | 你在设计器里画的那张图：节点 + 连线 + 每个节点的设置 | 一张公交线路图 |
| **版本** | 每次"发布"就把当前图纸**拍照冻结**成一个版本（1.0、2.0…），发布过的版本永远不会再变 | 线路图的历年存档版 |
| **绑定** | 把流程挂到某个模板上："这张表单提交时，走这条流程" | 在某个公交站牌上贴出这条线路 |
| **实例** | 某张具体单据提交后，按图纸真实跑起来的那一次审批。一张单据提交一次 = 一个实例 | 一辆正在跑这条线路的车 |
| **任务** | 实例走到某一站时，生成给具体某个人的"待办" | 这一站等着上车检票的乘客 |

三条最重要的关系，先记住，后面反复用到：

1. **画好 ≠ 能用**。流程必须先**发布**、再**绑定**到模板，用户的表单上才会出现「提交」按钮。这两步少一步，用户那边都毫无反应。
2. **改图不影响在途单据**。已提交的单据钉住提交那一刻的版本走完全程；你后来改了图、发了新版，只影响之后新提交的单据。
3. **一个模板可以绑多条流程**（提交时按条件路由，见 §5）；**一条流程只服务一个模板**。

## 2. 全景路线图

```
① 新建流程 → ② 画图 → ③ 配节点 → ④ 发布 → ⑤ 绑定模板 → ⑥ 真机验证
                                        ↑____________改版迭代____________|
```

下面用一个贯穿例子走完全程：**报销审批**——报销单提交后，金额 ≤ 5000 走「部门经理审批」，金额 > 5000 走「经理 + 总监两级审批」。这个例子会同时用到条件绑定和优先级，正是绑定环节最容易犯迷糊的地方。

## 3. 第一步到第四步：画出一条能发布的流程

### 3.1 新建流程

在应用左侧目录树上新建一个**流程**（和新建模板同级的入口），起名"报销审批（经理级）"。进入流程设计器——一块类似 Visio 的画布，初始只有一个**开始**节点。

### 3.2 画图

- 从左侧**形状库拖拽**节点到画布（拖拽是唯一的建节点方式）；
- 从节点边缘的连接桩**拉线**连接节点；
- 我们的经理级流程只需要：`开始 → 审批（部门经理）`。
- **不用画"结束"节点**——没有后续节点的末端，发布时系统会自动补上结束。

### 3.3 配置审批节点

点中审批节点，右侧属性面板里两件事必须配（不配发布会被拦）：

1. **审批人**：添加取人规则。常用的三种：
   - **直属主管**——谁提交的单，送谁的直属上级（我们的例子选这个）；
   - **角色**——如"财务角色"的所有人，可叠加"与发起人同部门"这类过滤；
   - **指定成员**——直接点名。
   - 一共有十种规则可选（表单人员字段、连续多级主管、发起人自选……详见 [for-end-users.md §5](for-end-users.md)），多条规则的结果取并集。
2. **按钮**：默认已带「同意」「不同意」。「不同意」必须配后果——整单终止 / 退回上一步 / 退回发起人。

其余设置（多人会签模式、字段权限、超时、去重策略、空兜底）都有合理默认值，第一条流程可以先全用默认。

> 两个默认值值得知道：审批人恰好是发起人自己、或刚在上一站审过 → 默认**自动通过**不重复审；某站解析不出任何人 → 默认**转管理员**，单据不会卡死。

### 3.4 发布

- 设计器里点「保存」存的是**草稿**——只有你看得到，对提交完全无效。
- 点**「发布」**才生成正式版本。发布前系统会做体检（发布校验），常见拦截：审批节点没配审批人/按钮、画了回路（设计器不允许画环，"打回重来"靠运行时的退回操作实现）、条件分支组没指定默认线。错误列表可点击，直接定位到出问题的节点。
- 校验通过 → 生成 **1.0 版本**。发布后的版本**永久冻结**，后续修改要再次发布生成 2.0。

照同样办法再建第二条流程"报销审批（总监级）"：`开始 → 审批（直属主管）→ 审批（连续多级主管，审到总监为止）`，发布。

现在两条流程都发布了——但用户的报销单上**仍然没有提交按钮**，因为还没绑定。

## 4. 第五步：绑定 —— 把流程挂到模板上（重点）

### 4.1 绑定在哪里配

绑定入口在**流程设计器**里：点画布空白处（不选中任何节点），右侧出现**流程设置面板**，其中有一个**「服务的模板」**区块。这就是绑定配置的地方，一共四个东西：

```
┌─ 服务的模板 ─────────────────────────────┐
│  模板：      [ 报销单            ▼ ]      │  ← 这条流程服务哪张表单
│                                          │
│  流转条件（不填=默认绑定，恒命中）：        │
│    [引导式 | 表达式]                      │  ← 什么情况下走这条流程
│    金额  ≤  5000        [+ 条件（且）]    │
│                                          │
│  优先级：  [ 0 ]                          │  ← 多条流程都命中时谁优先
│                                          │
│              [ 保存绑定 ]                 │
└──────────────────────────────────────────┘
```

### 4.2 三个配置项分别是什么意思

**① 模板**：下拉选这条流程要服务的表单。选定保存后，该模板提交时这条流程就成为候选。注意方向：是**在流程里选模板**，不是在模板里选流程。

**② 流转条件**：回答"什么样的单据走这条流程"。

- **不填 = 默认绑定**：任何单据都命中。模板只绑一条流程时通常留空即可。
- **引导式**（推荐）：下拉选字段、选比较符、填值，可以点「+ 条件（且）」叠加多条（全部满足才命中）。
- **表达式**：手写条件，字段引用的**唯一合法写法是 `{{field:字段ID}}`**，例如 `{{field:amount}} <= 5000`。写成 `${form.amount}`、直接写字段名等其他花样都不会报错、但**永远不命中**——这是最常见的"流程配了却不走"的原因。
- 条件里**只能用主表字段**（明细表字段不参与提交路由判断），下拉里列出的就是全部可用字段。

**③ 优先级**：数字越大越先判断。多条流程条件可能同时命中时，用它决定先看谁。

### 4.3 绑定我们的报销例子

| 流程 | 模板 | 流转条件 | 优先级 |
|---|---|---|---|
| 报销审批（总监级） | 报销单 | 金额 > 5000 | **10** |
| 报销审批（经理级） | 报销单 | （留空，默认绑定） | 0 |

思路：把**条件更苛刻的放高优先级**，把**默认兜底的留空放低优先级**。大额单先被总监级流程截住；其余一律落到经理级。

### 4.4 绑定的三条规则

1. **未发布的流程不能绑定**——保存绑定时会被直接拒绝。先发布，再绑定。
2. **一个模板可以绑多条流程**，靠条件 + 优先级分流（见 §5）。
3. **一条流程只能服务一个模板**。想给另一张表单配同样的审批路线？再建一条流程（可以照着画），分别绑定。

## 5. 提交时系统怎么选流程（把这一段吃透，路由就不迷了）

用户在报销单上点「提交」时，系统做的事：

```
找出该模板的全部绑定 → 按优先级从高到低逐条判断条件
  ├─ 恰好一条命中  → 自动走这条流程，提交完成
  ├─ 零条命中     → 弹「选择审批流程」窗口，让用户从候选里手选
  └─ 多条同时命中 → 同样弹窗手选
```

要点：

- **空条件 = 恒命中**。所以"一条带条件 + 一条空条件兜底"的组合永远能自动分流，不会弹窗（高优先级命中就走它；不命中则兜底恒命中）。
- **弹窗不是错误**，是兜底体验：系统拿不准时把选择权交给用户。但如果你希望用户永远不用选，就保证任何单据**恰好命中一条**——最简单的办法就是 §4.3 的"苛刻条件在上 + 空条件兜底在下"。
- **条件判断失败（如字段写错）按"不命中"处理**，不会报错中断提交——所以条件写错的表现是"总是走了另一条/总是弹窗"，排查时先检查 `{{field:xxx}}` 写法和字段 ID。
- 用户点弹窗的「取消」则完全无副作用，单据仍是草稿。

## 6. 第六步：真机验证

绑定保存后立即生效，走一遍完整链路：

1. 用普通账号打开报销单**填报页**，新增单据 → 动作栏出现**「提交」**按钮（没有出现？见 §8 FAQ 第 1 条）；
2. 填一张金额 3000 的单提交 → 应直接进入"审批中"（命中经理级）；填一张金额 8000 的 → 应也直接走总监级；
3. 用审批人账号进**任务中心 → 待办**，打开办理面板，点「同意」直到流程走完；
4. 回填报列表确认单据状态变为**「已通过」**且锁定。

任何一步不符合预期，对照 §8 排查。

## 7. 改版、解绑与在途单据

- **改流程图**：改完再次「发布」生成新版本。**在途单据不受影响**——它们钉住提交时的版本走完；新提交的单据走新版本。
- **只改文案**（节点名称、按钮文字、提示语这类不改路线的）：可对已发布版本直接生效，不用发新版本。
- **确实要让在途单据换走新版本**：管理员在流程管理面对指定实例执行「同步版本」，系统会校验该单据当前停留的节点在新版本里仍存在，校验不过拒绝同步，防止单据换轨后无路可走。
- **下线一条流程**：解除绑定即可——之后的新提交不再走它，在途实例照常走完。
- **改绑定条件/优先级**：改完保存立即对新提交生效，无版本概念。

## 8. 常见问题排查（按"用户报障"整理）

**1. "表单上没有提交按钮"**
按顺序检查：① 这条流程**发布**了吗（只保存草稿无效）？② 「服务的模板」里选对模板并**点了保存绑定**吗？③ 用户打开的是不是这个模板的填报页？

**2. "配了条件的流程，提交时永远不走它"**
九成是条件表达式写法问题：字段引用唯一合法写法是 `{{field:字段ID}}`；条件只支持**主表字段**；求值出错按"不命中"静默处理，不会报错提醒你。切到引导式模式重配一遍最稳。

**3. "每次提交都弹选择流程的窗口"**
说明命中了 0 条或多条。检查：多条绑定的条件是否互相重叠（都命中）？是否所有条件都不覆盖当前单据（都不命中）？加一条空条件的低优先级兜底绑定可以消灭"0 命中弹窗"。

**4. "发布被校验拦住了"**
错误列表可点击定位。高频三种：审批节点没配审批人或按钮；「不同意」按钮没选后果；条件分支组没指定默认线（分支必须有兜底去向）。

**5. "审批人离职/取不到人，单据会卡死吗"**
不会。取人时自动剔除离职者；剔完没人则走节点的空兜底（默认转管理员）。担心某站取不到人，就把该站兜底显式配成「指定人」。

**6. "改了流程，之前提交的单子乱了？"**
不会乱。在途单据钉提交时的版本走完（§7）。

**7. "想在流程里自动干点事（如审批通过后更新库存）"**
用**动作节点**：流程走到该节点时自动调用平台里的自动化能力，失败可重试/走错误分支/转人工。也可以让平台的动作编排订阅"流程事件"（如实例结束时触发模板上的动作）。详见 [for-end-users.md §4.7](for-end-users.md) 与 [for-human-developers.md §10](for-human-developers.md)。
